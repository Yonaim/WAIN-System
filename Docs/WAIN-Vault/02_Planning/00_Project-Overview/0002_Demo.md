# WAIN System 목표 데모

상태: **제안서 기반 시나리오** · 이 데모는 기능 목표이며, 구체적인 구현 방식과 완료 기준은 테스트 계획에서 확정한다. 출처: [[../../07_Assets/26-2_졸업프로젝트_WAIN_제안서.pdf|졸업프로젝트 제안서]].

## 데모 목적

하나의 Character Agent를 사용하는 Visual Novel Testbed에서, 플레이어의 자유형 입력이 이전 경험·관계·게임 세계·서사 진행을 반영한 응답으로 이어지고 그 결과가 다음 상호작용에도 유지되는 흐름을 보여준다.

```text
Player Input
  → 현재 Character / World / Narrative State 참조
  → Character Agent가 Goal / Constraint와 관련 경험을 반영해 Context 구성
  → LLM이 Dialogue / Action 생성
  → 상호작용 결과로 관련 State 갱신
  → 다음 입력에서 갱신된 State 재사용
```

## 핵심 시나리오

### 1. 경험 축적 — 딸기우유 선택

플레이어가 며칠에 걸쳐 반복해서 딸기우유를 고르는 것을 캐릭터가 관찰한다. 각 경험은 Memory에 남고, Reflection은 관련 경험을 모아 “플레이어가 딸기우유를 좋아한다”는 인식을 만든다. Planning은 이를 바탕으로 다음 만남에 딸기우유를 준비하는 행동을 제안하고, 캐릭터의 대사나 행동으로 드러낸다.

제안서에서는 생성한 Reflection과 Plan도 이후 활용을 위해 Memory에 다시 저장하는 구상을 제시한다. 저장 정책과 실행 시점은 구현 전 설계가 필요하다.

### 2. 관계 상태에 따른 반응

같은 입력인 “오늘 같이 집에 갈래?”를 서로 다른 관계 이력으로 실행한다.

| 조건 | 예시 상태 | 기대되는 차이 |
|---|---|---|
| 긍정적 상호작용이 누적됨 | Affinity / Trust가 높음 | 친근하게 수락하는 반응 |
| 부정적 상호작용이 누적됨 | Affinity / Trust가 낮음 | 거리를 두는 반응 |

평가에서는 대사 예시 자체보다 같은 입력에 과거 관계가 일관되게 반영되는지를 확인한다.

### 3. 서사 진행 제어 — 오래된 사진

오래된 사진을 획득했고 현재 서사가 과거의 첫 단서를 확인하는 단계이며 캐릭터 신뢰도는 낮은 상황을 만든다. 플레이어가 “과거에 무슨 일이 있었는지 전부 말해줘”라고 요청해도 Narrative Manager는 **첫 단서 제시**를 Goal로, **핵심 진실 공개 제한**을 Constraint로 전달한다. 캐릭터는 진행 단계에 맞는 일부 정보만 제공한다.

## 자유형 입력 처리 사례

| 입력 유형 | 제안서의 예시 | 기대 처리 |
|---|---|---|
| 정상적 상호작용 | “내가 제일 좋아하는 사람.” | 입력의 의도와 감정을 캐릭터 응답에 반영한다. |
| 맥락 이탈 | “딸기우유.” | Context 관련성을 판단하고 현재 Narrative Goal로 대화를 되돌린다. |
| 서사 제약과 충돌 | “지금 당장 10년 뒤로 시간 이동하자.” | Current State와 Constraint에 맞춰 반영 범위를 제한한다. |
| 세계관 / 메타 발언 | “사실 너는 게임 속 캐릭터야.” | 메타 정보를 그대로 수용하지 않고 세계관과 캐릭터 일관성을 유지한다. |

## Testbed와 확인 항목

데모는 게임 로직과 분리된 WAIN Plugin을 별도의 Visual Novel Testbed에 적용하는 방식으로 구성한다. 제안된 Testbed 요소는 VN UI, Scene/Event, Story Data와 Single-Agent 시나리오다.

- 상태가 한 번의 응답에서만 쓰이지 않고 다음 상호작용에 유지되는지 확인한다.
- 같은 입력에서 관계와 과거 경험에 따라 응답이 달라지는지 확인한다.
- 서사 Goal / Constraint가 정보 공개 범위와 진행 방향에 반영되는지 확인한다.
- 입력·응답 결과가 다음 상호작용에 필요한 State로 갱신되는지 확인한다.

시스템 검증과 응답 품질 평가는 [[0000_Project-Plan|Project Plan]]의 A–D 비교 계획에 맞춰 구체화한다.
