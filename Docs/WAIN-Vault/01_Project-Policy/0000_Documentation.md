# 문서 정책

이 볼트는 WAIN System의 제안 목표, 현재 프로토타입 범위, 구현 결과를 구분해 기록한다. 제안서에 적힌 기능은 구현과 검증을 마치기 전까지 완료된 기능으로 표현하지 않는다.

## 상태 표기

- **제안 목표**: 졸업프로젝트 제안서에서 목표로 제시한 기능이나 평가 계획.
- **계획**: 구현 순서와 범위가 정해졌지만 아직 완료되지 않은 작업.
- **구현됨**: 저장소의 코드에서 확인할 수 있는 기능.
- **검증됨**: 재현 가능한 테스트나 평가로 동작을 확인한 기능.
- **미정**: 제안서에서 구체적으로 정하지 않았고 구현 전에 결정할 내용.

실제 구현 및 검증 상태는 코드와 결과를 확인한 뒤 [[TODO|TODO]]에 반영한다.

## 문서 책임

- `00_Start/`: 볼트 공통 사용법과 재사용 템플릿.
- `01_Project-Policy/`: WAIN의 공식 용어, 문서 작성 원칙, 코드·주석·커밋 관례.
- `02_Planning/`: 프로젝트 목표, 구현 단계, 데모 시나리오와 진행 계획.
- `03_Architecture/`: 시스템 구성, 모듈 책임, 상태와 상호작용 흐름.
- `04_ADR/`: 중요한 설계 선택과 대안, 선택 이유.
- `05_Development/`: 구현 메모, 실험, 디버깅 기록.
- `06_Testing/`: 테스트 원칙, 시나리오, 평가 결과.
- `07_Assets/`: 졸업프로젝트 제안서와 발표 자료 등 원본 자료.

프로젝트 목표와 프로토타입 범위는 [[../02_Planning/00_Project-Overview/0000_Project-Plan|Project Plan]], 단계별 계획은 [[../02_Planning/00_Project-Overview/0001_Roadmap|Roadmap]]을 기준으로 한다. 원본 제안 자료는 [[../07_Assets/26-2_졸업프로젝트_WAIN_제안서.pdf|졸업프로젝트 제안서]]와 [[../07_Assets/26-2_졸업프로젝트_WAIN_제안서_발표대본|제안서 발표 대본]]을 참고한다.

## 출처와 최신성

제안서는 프로젝트의 문제 정의, 목표, 프로토타입 범위와 평가 계획의 출처다. 제안서에 없는 세부 구현을 이미 확정된 사실처럼 추가하지 않는다. 후속 설계 결정이나 검증 결과가 제안과 달라지면 Architecture 또는 ADR에 변경 이유를 기록하고, 영향을 받는 계획 문서를 함께 갱신한다.

## 파일명 규칙

- 문서 파일은 디렉터리별로 `0000_이름.md` 형식의 네 자리 번호를 사용한다.
- Overview, Guide, Index처럼 폴더의 진입점은 `0000`으로 둔다.
- 주차 계획을 만들 때는 `00_Start/Templates/`의 Weekly Overview와 Weekly Details 템플릿을 복사한다.
- 번호는 폴더 내 정렬을 위한 것이며, 프로젝트 일정이나 완료 상태를 뜻하지 않는다.
