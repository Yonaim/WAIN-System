# 문서 정책

> **한 줄 요약:** WAIN의 설계 기준, 구현 사실, 연구 판단과 실행 결과를 서로 구분한다.

## 문서의 역할

| 위치 | 내용 |
|---|---|
| `01_Project-Policy` | 용어, 문서 작성, 코드·커밋·주석 관례 및 템플릿 |
| `02_Architecture` | 아키텍처, 실행 흐름, 데이터·모듈 계약, 소스 색인 |
| `03_Development` | 진행 중인 구현, 설계 결정과 미결 사항 |
| `04_Experiments` | 테스트 계획, 실행 결과와 성능 측정 근거 |
| `05_Research` | 연구 문제, 선행 연구, 비교 설계와 평가 한계 |
| `06_Assets` | 발표 자료, 대본 등 원본 자료와 색인 |

## 근거와 상태

1. 코드는 현재 구현 동작의 근거다. 발표 자료와 설계 문서는 코드에 없는 기능을 구현 완료로 만들지 않는다.
2. [[전체|설계 인계 문서]]의 확정 결정과 미확정 질문을 구분한다.
3. 발표 PDF와 대본은 2026-10-28 시점의 설명 근거다. 이후 변경된 설계는 현재 기준과 결정 기록을 따른다.
4. 테스트 계획, 실행 결과, 해석을 분리한다. 실행하지 않은 시험과 수치를 결과로 기록하지 않는다.
5. 예시 인터페이스, JSON, 파라미터는 확정된 계약이 아니면 **개념 예시**로 표시한다.
6. 링크를 바꾸거나 문서를 이동하면 Obsidian 링크를 확인한다.

## 한 개념의 정본

계산·데이터 계약은 Architecture, 진행 중인 작업은 Development, 검증 결과는 Experiments, 연구 질문과 해석은 Research에 둔다. 같은 내용을 여러 문서에 복제하기보다 정본 링크를 연결한다.
