# 문서 정책

> **한 줄 요약:** 현재 구현의 근거와 진행 기록을 분리해 유지한다.

## 문서의 역할

| 위치 | 내용 |
|---|---|
| `01_Project-Policy` | 용어, 문서 규칙, 코드·커밋 관례와 재사용 템플릿 |
| `02_Architecture` | 현재 시스템 흐름, 계약, 소스 코드 지도 |
| `03_Development` | 진행 중인 작업과 현재 설계 선택 |
| `04_Experiments` | 검증·테스트·성능 실험의 계획과 실제 결과 |
| `05_Research` | 연구 문제, 선행연구, 기여 후보와 근거 기반 판단 |

## 작성 원칙

- 한 개념의 현행 정의는 가장 적합한 한 문서에 정본으로 둔다.
- 구현 사실은 코드·요구사항·실행 결과 등 근거를 함께 기록한다. 추정은 추정이라고 표시한다.
- Architecture에는 작업 일지와 개인적인 의견 대신 현재 동작과 지원 범위를 기록한다.
- 테스트 계획과 실행 결과를 구분한다. 실행하지 않은 테스트·수치를 통과한 것으로 기록하지 않는다.
- 변경된 문서는 관련 파일이나 요구사항 링크를 포함하고, 마지막 확인 날짜를 갱신한다.
- 프로젝트별 사실은 WAIN 저장소의 코드, 요구사항, 실행 근거로 확인한다.
