# C++ 주석 작성 규칙

> **한 줄 요약:** 파일과 함수 설명은 Doxygen 주석으로 책임·계약을 설명하고, 인라인 주석은 코드만으로 드러나지 않는 이유를 기록한다.

## 기본 원칙

| 원칙 | 기준 |
|---|---|
| 형식 통일 | 파일과 공개 함수 설명은 `/** ... */` 형식으로 작성한다. |
| 목적 중심 | 코드 동작을 반복하지 말고 책임·계약·주의점을 설명한다. |
| 간결성 | 필요한 정보만 남기고 구현을 줄마다 해설하지 않는다. |
| 최신성 | 코드의 동작이나 계약이 바뀌면 주석도 함께 수정한다. |
| 선택적 작성 | 이름과 선언만으로 충분히 명확한 단순 함수에는 주석을 생략한다. |

## 파일 상단 주석

C++ 헤더와 구현 파일에는 include보다 앞에 `@file`과 `@brief`를 포함한 설명을 둔다. 여러 파일에 걸친 불변조건이나 중요한 설계 제약이 있을 때만 `@note`를 추가한다.

```cpp
/**
 * @file WAINCharacterState.h
 * @brief Character Agent의 지속 상태와 상태 전이 데이터를 정의한다.
 * @note 상태 필드는 직렬화 계약과 일치해야 한다.
 */
```

파일 주석은 파일의 목적과 범위를 설명한다. 선언된 모든 타입과 함수를 목록처럼 나열하지 않는다.

## 함수 주석

함수의 역할을 `@brief`로 설명한다. 필요하면 입력 조건에 `@param`, 반환값의 의미에 `@return`, 실패 조건에 `@throws` 또는 프로젝트가 사용하는 오류 표기를 적는다.

```cpp
/**
 * @brief 대화 요청에 사용할 현재 캐릭터 상태와 관련 기억을 구성한다.
 * @param CharacterId 컨텍스트를 만들 캐릭터 식별자.
 * @return 외부 요청에 사용할 구조화된 컨텍스트.
 */
FWAINRequestContext BuildRequestContext(const FName& CharacterId);
```

함수 이름만으로 드러나지 않는 전제 조건·부수 효과가 있거나, 반환값의 단위·소유권·유효 기간, 실패 조건, 데이터 순서와 호출 계약을 설명해야 할 때 주석을 작성한다. 단순 getter에는 설명을 반복하지 않는다. 선언과 정의에 같은 설명을 중복 작성하지 말고 공개 API 설명은 헤더 선언에 둔다.

## 인라인 주석

짧은 설명이나 특정 코드 옆의 설명에는 일반 `//` 주석을 사용할 수 있다. 알고리즘의 이유, 예상하기 어려운 제약 또는 의도적인 예외를 설명하고 코드에서 바로 읽히는 사실을 반복하지 않는다.

```cpp
// 외부 응답이 늦게 도착할 수 있어 요청 식별자를 먼저 확인한다.
if (Response.RequestId != PendingRequestId)
{
    return;
}
```

## 금지할 패턴

- 주석과 코드가 서로 다른 동작을 설명하는 상태로 방치하지 않는다.
- 함수 본문을 한 줄씩 번역하거나 변수 이름을 문장으로 반복하지 않는다.
- 근거와 담당 범위가 불분명한 `TODO`, `FIXME`를 남기지 않는다. 필요한 작업은 작업 문서에 기록하고 코드 주석에는 추적 가능한 이유를 남긴다.
- 모든 사소한 함수에 기계적으로 주석을 붙이지 않는다.
