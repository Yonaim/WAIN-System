# Setup Questionnaire — Agent Question Bank

> **질문 목록을 한꺼번에 제시하는 설문지가 아니다.** 먼저 저장소를 읽고 판단 가능한 답은 확인한다. 남은 **필수 결정**만 간결하게 질문한다.

## 10. 진행 방식

1. `확인됨`(소스·기존 설정에서 직접 확인), `추천`(프로젝트 특성에 따른 제안), `미정`(질문 필요)을 분리한다.
2. **설정을 진행하기 위한 선택이 여러 개이고, 기존 정보로 결정할 수 없을 때만 질문한다.** 관련 질문은 필요한 수만큼 묶되 과도한 설문은 피한다.
3. 기본값을 제안할 수 있지만 사용자 승인 없이 빌드 시스템 교체, 엔진 파일 변경, 기존 툴 설정 덮어쓰기를 결정하지 않는다.
4. 사용자가 이미 제공한 정보는 재질문하지 않는다. 미정인 항목은 `미정`이라고 두고 안전한 범위부터 진행한다.
5. Setup 직후에는 어떤 값을 **확인했는지**, 어떤 값을 **가정했는지**, 어떤 검증을 **실행했는지** 짧게 요약한다.

## 20. 최소 신규 프로젝트 예시

- **C + 간단한 CLI**: Q1 프로젝트 목적, Q2 C 표준, Q3 운영체제/컴파일러가 미정이면 확인 → 기본 Make 검토 → `Source/*.c` 배치 → 포맷+컴파일 연결.
- **C++ + 라이브러리/SDK**: Q1 결과물, Q2 표준, Q5 SDK, Q3 플랫폼이 중요 → CMake 추천 → 실제 타깃별 후크 연결.
- **Unreal 프로젝트**: `.uproject`·엔진 버전·타깃 목록 확인 → 기존 UBT 유지 → Game/Editor 타깃의 사전 후크를 필요한 부분에 병합 → Live Coding 경로 확인.

## 30. Setup 이후 기록할 곳

프로젝트의 **목적과 범위는 Project Brief**, 언어·OS·SDK 제약은 Constraints, 기능 기준은 Requirements, 진입 경로는 Flows/Source Map에 기록한다. **어떤 템플릿을 복사했는지, 언제 수정했는지** 같은 작업 이력은 Work Log/ADR/Validation에만 기록한다. Project Brief를 빌드 작업 일지로 사용하지 않는다.
